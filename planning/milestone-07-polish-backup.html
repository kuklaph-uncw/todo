Milestone 7

Polish and Backup

Close gaps that determine whether the app is pleasant and trustworthy enough for real daily use.

AC-24 A-1..A-6

Goal

The app is keyboard-friendly, accessible, readable on narrow screens, clear in empty/error states, and documented for local backup and restore.

Scope

Included

  • Keyboard shortcuts: Cmd/Ctrl+Enter for journal and TODO submit, / for TODO search.
  • Visible focus states and real button elements.
  • Labels for all inputs.
  • Delete and clear-completion confirmations.
  • Responsive layout checks for narrow screens.
  • Inline validation errors for HTMX and non-HTMX fallback paths.
  • README with run, backup, restore, and privacy notes.
  • Manual smoke test checklist.

Excluded

  • Automated backup script. Future enhancement.
  • LAN access and authentication.
  • Print stylesheet unless it becomes needed during use.
  • Advanced shortcuts such as g t, g r, and n.

Documentation Requirements

DocumentMust Include
README.mdInstall, run, local-only behavior, database path, no telemetry, backup, restore, smoke test.
.gitignoretracker.db, SQLite sidecar files, local environment files.
In-app help textMinimal labels and empty states only. Avoid instructional clutter.

Backup Plan

# Backup
Copy tracker.db to a dated backup path.

# Restore
Stop the server, replace tracker.db with the backup copy, restart the app.

The PRD shows Unix-style commands. If this remains Windows-first, include PowerShell equivalents in the README during this milestone.

TDD and Verification Plan

  1. RED: tests for fallback error rendering in journal, TODO, and review forms where practical.
  2. GREEN: standardize inline error fragments and normal-page fallback errors.
  3. RED: client behavior tests or manual-script checklist for shortcut behavior.
  4. GREEN: implement minimal shortcut behavior without complex client state.
  5. VERIFY: manual responsive and accessibility pass on all pages.
  6. VERIFY: run the full smoke test from the PRD and record any failures.

Smoke Test

  • Start the app.
  • Add three journal entries for today using multiline capture.
  • Add one journal entry for yesterday.
  • Add three TODOs.
  • Mark two TODOs done.
  • Star one journal entry.
  • Confirm today's summary counts are correct.
  • Open review for this week.
  • Confirm entries and completed TODOs appear on the correct dates.
  • Copy Markdown.
  • Download Markdown.
  • Restart the server.
  • Confirm data persisted.

Done Gate

  • All v1 acceptance criteria pass.
  • README documents manual backup and restore.
  • Database file is excluded from source control.
  • Core actions are usable by keyboard.
  • Pages work on narrow screens.
  • Destructive actions require confirmation.
  • Manual smoke test is complete.
