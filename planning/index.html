Planning Package

Build the useful local tracker before anything advanced.

This plan keeps the journal as the main artifact, adds TODOs only where they support daily review, treats tags as the organizing primitive, and includes AI-readable exports without making AI summaries part of v1.

Implementation Start Rule (historical)

This callout described the pre-implementation state: "create or initialize the app project first; the current directory only contains prd.md and planning\, and it is not a Git repository." As of 2026-07-01, Milestone 1 (Foundation) and a 4-page visual shell are implemented under src\/public\/tests\, and the repo is a normal git repository.

Milestone Sequence

  1. Foundation. Create the Bun app shell, SQLite connection, migrations, base layout, static assets, date helpers, validation helpers, tag storage, and route skeleton.
  2. Day View Journal. Build the daily capture loop: date navigation, multiline entry creation, inline edit/delete, tags, highlights, and draft protection.
  3. Day View TODO Panel. Add lightweight TODO tracking beside the journal with tags and completion metadata that does not silently change.
  4. Review Output. Build date-range review, presets, stats, tag breakdown, highlight summary, grouped accomplishment output, and highlights-only mode.
  5. Markdown and AI Export. Add server-generated Markdown, date-range JSON/JSONL export for AI context, copy action, manual fallback, and file download.
  6. TODO Manager. Add the secondary full task management page with filters, search, tag editing, detail edits, highlight toggles, and explicit completion clearing.
  7. Polish and Backup. Add keyboard shortcuts, empty states, inline errors, confirmations, README, manual backup docs, and smoke-test checklist.

Global Technical Decisions

AreaDecisionReason
RuntimeBun with Bun.serve()Matches PRD, no separate framework or build step.
DatabaseSQLite through bun:sqliteLocal-first storage with simple backup path.
OrganizationFirst-class tags, not a single category fieldTags cover the category use case and allow multiple labels per entry or TODO.
RenderingServer-rendered HTML plus HTMX fragmentsSimple state model, works without heavy client app code.
DatesLocal YYYY-MM-DD for grouping; UTC ISO for audit timestampsPrevents midnight UTC drift and protects review accuracy.
DeletionSoft delete for journal entries and TODOsProtects history and export integrity.
ReviewShared review query/model for UI, Markdown, and AI-readable exportAvoids divergent export behavior.
AI accessExport-first: date-range Markdown plus JSON/JSONLLets agents summarize six-month ranges without adding API or MCP surface area in v1.

Global Test Strategy

Unit Tests

  • Local date formatting and date range preset calculations.
  • Multiline journal splitting and validation.
  • Tag parsing, normalization, deduplication, and assignment.
  • TODO validation and completion transition rules.
  • Markdown formatting and escaping rules.
  • AI export shape and date-range filtering.
  • Soft-delete query behavior.

Integration Tests

  • Add, edit, star, and soft-delete journal entries.
  • Add TODO, mark done, reopen, re-close, and preserve metadata.
  • Review query includes journal entries and completed TODOs.
  • Review query excludes soft-deleted records.
  • Markdown and AI-readable exports return expected content.
